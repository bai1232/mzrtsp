# 版本与发布要求

> 本文件是项目的**强制要求**。任何一次版本发布都必须满足以下全部条款，缺一不可。

## 一、每一版都必须上传 Git

- **每一版都必须上传 Git。**
- 发布提交必须推送到远程仓库（`main` 分支），本地提交不算发布。
- 远程仓库中必须能找到该版本对应的提交，且该提交可被完整拉取。

## 二、每个版本必须打 tag

- 每个版本必须打 tag，格式：`vX.Y.Z`，例如 `v0.1.0`。
- tag 必须打在该版本的发布提交上。
- tag 必须推送到远程：`git push origin vX.Y.Z`（或 `git push --tags`）。
- 禁止使用不带 `v` 前缀或非三段式的 tag（如 `1.0`、`release-1`、`v1`）。

## 三、版本号遵循语义化版本

版本号格式固定为 `vX.Y.Z`，三段含义如下：

| 位 | 含义 | 递增时机 |
|---|---|---|
| `X` | **不兼容变更** | 接口/协议/行为发生不兼容改动 |
| `Y` | **新增功能** | 向后兼容地新增功能 |
| `Z` | **修复** | 向后兼容地修复缺陷 |

补充约定：

- 递增高位时，低位清零（如 `v1.2.3` 出现不兼容变更后，下一版为 `v2.0.0`）。
- 尚未正式发布的开发版本可写作 `v0.Y.Z`；`v0.x` 阶段允许存在不兼容变更。
- 文档、注释、内部重构等不影响功能的改动，可只递增 `Z`。

## 四、每个版本必须可回滚

- **每个版本必须可回滚**：任何时刻都能从远程仓库回到上一个稳定版本，并恢复到可构建、可运行的状态。
- 回滚不得依赖本地未提交的改动或临时文件。
- 每个版本必须满足：该 tag 对应的代码能独立完成构建（`cmake --build`）并通过测试。
- 回滚方式（任选，按场景）：

```bash
# 1. 查看并切到指定版本
git fetch --tags
git checkout v0.1.0

# 2. 以新提交的形式回滚某次改动（推荐，保留历史）
git revert <commit-id>
git push origin main

# 3. 强制回到某个 tag 的状态（会改写历史，需团队确认）
git reset --hard v0.1.0
git push --force-with-lease origin main
```

## 五、发布检查清单

每次发版前逐项确认：

- [ ] 代码已提交到本地仓库，提交信息符合规范（`feat|fix|docs|test|build|refactor|perf`）
- [ ] 已推送到远程仓库（`git push origin main`）
- [ ] 版本号已按语义化规则确定（`X` / `Y` / `Z` 判断无误）
- [ ] 已在发布提交上创建 tag：`git tag -a vX.Y.Z -m "release vX.Y.Z"`
- [ ] tag 已推送到远程：`git push origin vX.Y.Z`
- [ ] 该 tag 的代码已验证可独立构建、测试通过（保证可回滚）
- [ ] `CHANGELOG.md` 已更新本版内容

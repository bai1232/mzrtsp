# mzmedia 需求规格说明（定稿）

> 版本：v0.1 设计基线 · 状态：**已定稿** · 最后更新：2026-09
>
> 本文是项目的**唯一规格来源**。任何实现与本文冲突时，以本文为准；修改规格必须先改本文并提交。

## 1. 项目定位

**一个支持多格式的流媒体文件服务器：输入多种媒体文件，输出多种流媒体格式，中间按需转封装或转码。**

一句话技术画像：**自研 epoll 网络底座 + FFmpeg 编解码/封装内核 + 一源多消费者的实时分发**。网络与并发全部自研，FFmpeg 只负责 demux/mux/decode/encode 这类重型但通用的工作。

## 2. 用户与场景

| 用户 | 场景 | 关注点 |
|---|---|---|
| 开发者 | 本地文件 → 浏览器直接播放，免装播放器 | 启动简单、打开网页就能看 |
| 运维 | 媒体格式转换、协议转换（转封装/转码） | 转换正确、批量、资源可控 |
| 学习者 | 理解**解封装 → 解码 → 编码 → 封装**全链路 | 代码可读、分层清晰、有文档 |

## 3. 核心流水线

```
                         ┌──────────────── MedaSource（一源一份输出）────────────────┐
输入 demux ──► 可行性判定 │                                                          │
（MP4/H264/MKV/TS/RTSP）  │  分支 A：remux（零拷贝，AVPacket 直通）                   │
                         │      demux ──► mux(FLV/TS) ──┐                            │
                         │  分支 B：transcode（v0.2+）   │                            │
                         │      demux ──► decode ──► filter ──► encode ──► mux ──┐    │
                         └─────────────────────────────────────────────────┬─────┘    │
                                                                           │          │
                                              ┌────────────────────────────┴───────┐  │
                                              │  Output 层：HTTP-FLV / HLS 分片     │  │
                                              └───────────────┬───────────────────┘  │
                                                              │ 每客户端独立队列/连接
                                          ┌───────────────────┼───────────────────┐
                                     Client A            Client B            Client C
```

**判定规则**（"按需"的确切含义）：

1. 目标封装格式是否支持该编码？（见 `CODEC_MATRIX.md`）
2. 输出格式的目标播放端是否支持该编码？（HTTP-FLV → 浏览器，仅 H264/AAC）
3. 两者皆为"是" → **remux**（不解码，零拷贝）
4. 任一为"否" → 若开启了转码能力则 **transcode**；否则**拒绝并返回明确错误**，不静默降级

| 能力 | v0.1 | v0.2 | v0.3 |
|---|---|---|---|
| 输入 MP4 | ✅ | | |
| 输入 H264 裸流 | ✅ | | |
| 输入 MKV / TS | | ✅ | |
| 输入 RTSP（作为客户端拉流） | | | ✅ |
| 视频 H264 | ✅ | | |
| 音频 AAC | ✅ | | |
| 输出 HTTP-FLV | ✅ | | |
| 输出 HLS | | ✅ | |
| 转封装 remux | ✅ | | |

| H265 / HEVC | — | — | **不做** |

> **H265 决策记录**：HTTP-FLV 的浏览器播放端（flv.js / MSE）不支持 HEVC，与"浏览器能播"的成功标准直接冲突。经权衡，**v0.1–v0.3 明确不做 H265**，矩阵中移除，避免出现"支持了却播不了"的假能力。若未来要做，须走 HLS + fMP4(HEVC) 独立分支，并单独立规格。

## 5. 功能需求

### 5.1 媒体源（FR-1）

- **FR-1.1 一源一份输出**：同一个媒体源（同一个输入文件/URL）在任一时刻**只存在一份转码/封装任务**；N 个客户端**共享**这份输出，各自持有独立的输出连接与发送队列。
- **FR-1.2 直播式重放**：文件输入按**直播流**方式输出——从头开始按时间轴节流推送，支持可选循环；**不支持 seek**（HTTP-FLV 为直播语义）。
- **FR-1.3 按需启动与释放**：转码/封装任务 **lazy 启动**（首个客户端接入时启动），最后一个客户端断开后**空闲 60s 释放**，释放须回收全部 FFmpeg 上下文、文件描述符与线程。
- **FR-1.4 GOP 缓存**：媒体源缓存**最近 1 个 GOP**；新客户端从**关键帧**开始发送，保证首帧可解码（不花屏）。
- **FR-1.5 生命周期**：源释放后，其占用的内存、fd、线程数须回到接入前水平。

### 5.2 输入（FR-2）

- **FR-2.1** v0.1 支持 `MP4`（含 `mov`）与 `H264 Annex-B 裸流`。
- **FR-2.2** v0.2 支持 `MKV`/`Matroska` 与 `MPEG-TS`。
- **FR-2.3** v0.3 支持以 `RTSP` URL 作为输入（以 FFmpeg 为客户端拉流），须支持**断流检测与重连**。
- **FR-2.4 边界处理**：损坏文件、无视频轨、纯音频、可变帧率（VFR）、时长未知，均须给出明确错误或降级行为，**不得崩溃**。

### 5.3 输出（FR-3）

- **FR-3.1 HTTP-FLV（v0.1）**：`Content-Type: video/x-flv`，HTTP/1.1 **chunked** 传输，连接建立后立即发送 FLV Header + AVC sequence header（SPS/PPS），随后持续推流。
- **FR-3.2 HLS（v0.2）**：`mpegts` 切片，**切片时长 2s**，**滑动窗口 6 片**，`.m3u8` 包含 `#EXT-X-MEDIA-SEQUENCE` 与 `#EXT-X-TARGETDURATION`。
- **FR-3.3 音频**：v0.1 支持 AAC 转发（FLV `AAC sequence header` + raw AAC）；无音频输入时输出**纯视频流**，不得报错。
- **FR-3.4 音视频同步**：以**音频为主时钟**；无音频时以视频 PTS 为时钟。时间戳统一转换到输出格式基准（FLV → 毫秒；TS → 90kHz）。
- **FR-3.5 节流**：文件输入按源时间轴与**墙钟对齐**推送，不得以磁盘速度全速灌入。

### 5.4 HTTP 服务（FR-4）

- **FR-4.1** 路由：`GET /live/<name>.flv`、`GET /hls/<name>.m3u8`、`GET /hls/<name>-<seq>.ts`、`GET /api/stats`、`GET /`（内置播放测试页）。
- **FR-4.2** 支持 `chunked` 响应、`Content-Length` 静态响应、`Range` 请求（HLS 切片与静态文件）。
- **FR-4.3 CORS**：输出接口默认带 `Access-Control-Allow-Origin: *`，保证 flv.js 跨域可播。
- **FR-4.4** 连接上限（默认 64，可配）、读空闲超时（默认 60s）、写阻塞超时（默认 30s）。
- **FR-4.5** 404 / 405 / 500 返回规范响应并记录日志。

### 5.5 分发与背压（FR-5）

- **FR-5.1** 每个客户端独立发送队列，上限 **64 帧或 8MB**（先到者为准）。
- **FR-5.2 慢客户端策略**：队列溢出时**优先丢弃非关键帧**并累加丢弃计数；连续阻塞超过 **30s** 则**断开该客户端**，不影响其他客户端与源。
- **FR-5.3 隔离性**：任一客户端异常（断连、不读数据）不得影响源任务与其他客户端。

### 5.6 可观测性（FR-6）

- **FR-6.1** `/api/stats`（JSON）暴露：当前源数、客户端数、每源码率、转码实时倍数、丢帧数、累计字节、运行时长。
- **FR-6.2** 日志：分级、异步、滚动文件（默认 `logs/mzmedia.log`，默认级别 `Info`）。
- **FR-6.3** 关键事件落日志：源创建/释放、客户端接入/断开、转码启动/失败、错误与异常。

### 5.7 配置（FR-7）

- **FR-7.1** 命令行参数：监听端口、媒体文件路径、日志级别、是否循环、转码开关。
- **FR-7.2** 未提供的参数使用内置默认值，程序在**零参数**下也应能启动内置测试页。

## 6. 非功能需求

| 编号 | 需求 | 目标值 |
|---|---|---|
| NFR-1 | 首帧时间（本地） | < 1s |
| NFR-2 | 并发客户端（同源共享） | ≥ 10 路，无串流、无崩溃 |
| NFR-3 | 连续运行稳定性 | 1 小时，RSS 增长 < 5MB/h，fd 无泄漏，错误日志 0 条 |
| NFR-4 | remux CPU 占用 | 单路 < 5% 单核（证明零拷贝） |
| NFR-5 | 转码速度（v0.2） | ≥ 1.0x 实时（1080p→720p，x264 veryfast） |
| NFR-6 | 资源回收 | 客户端断开后，队列/上下文/fd **100% 回收** |
| NFR-7 | 代码质量 | `-Wall -Wextra` 零警告；单元测试覆盖协议解析、缓冲、时间戳换算、codec 判定 |
| NFR-8 | 可移植性 | Linux x86_64；C++17；FFmpeg **4.4.x**（版本锁定，见下） |

## 7. 约束

- **操作系统**：Linux（网络层基于 epoll，不做 Windows 兼容）
- **语言标准**：C++17
- **外部依赖**：FFmpeg —— `libavformat` / `libavcodec` / `libavutil`（v0.2 起追加 `libswscale`、可选 `libavfilter`）
- **版本锁定**：实测环境为 **FFmpeg 4.4.2**（libavformat 58.76.100 / libavcodec 58.134.100 / libavutil 56.70.100 / libswresample 3.9.100）。**4.x 与 5.x/6.x API 不兼容**（`avcodec_close` 弃用、声道布局字段变更），项目按 4.x 编写并在 CMake 中做版本探测与明确报错。
- **网络底座**：**自研**（epoll 事件循环、TCP 封装、线程池、定时器、日志），不引入 asio/libevent。
- **许可证**：项目本体 MIT；运行时链接的 FFmpeg（Ubuntu 构建包含 GPL 组件 libx264/libx265）在**分发**时受 GPL 约束，须在 README 声明。

## 8. 成功标准

- **SC-1**：本地 MP4 → HTTP-FLV，浏览器能播（内置测试页 + flv.js）
- **SC-2**：同一架构后续能加格式，**不改核心**（新增输入/输出只增实现，不动 `MediaSource`/分发/网络层）
- **SC-3**：多客户端并发不崩（≥10 路同源）
- **SC-4**：连续运行 1 小时稳定（NFR-3）

> 每条成功标准都必须有**可执行的验证手段**，见 `TESTING.md`。

## 9. 明确不做（Out of Scope）

- H265/HEVC、AV1、VP9 等编码
- 音频转码、多音轨、多码率（ABR）切换
- WebRTC、RTMP 推流接收、DASH、加密（DRM）、鉴权
- 录像/回看、GOP 之外的长缓存、分布式/集群、GPU 转码
- Windows / macOS 兼容
- 点播 seek（HTTP-FLV 直播语义；HLS 亦按直播切片）

## 10. 术语表

| 术语 | 含义 |
|---|---|
| **demux / 解封装** | 从容器（MP4/MKV/TS）中分离出音视频基本流 |
| **mux / 封装** | 把音视频基本流写入容器（FLV/TS） |
| **remux / 转封装** | 只换容器，不重编码（零拷贝，CPU 极低） |
| **transcode / 转码** | 解码后重新编码（CPU 高，可改分辨率/码率） |
| **AVPacket** | FFmpeg 中编码后的一个数据包（压缩数据） |
| **AVFrame** | FFmpeg 中解码后的原始帧数据 |
| **GOP** | 两个关键帧之间的图像组，缓存 1 个 GOP 可让新客户端从关键帧起播 |
| **AAC sequence header** | FLV 中携带 AAC 音频配置（AudioSpecificConfig）的初始化包 |
| **直播式重放** | 把文件当作直播源按时间轴节流推送，不支持 seek |
